# 📚 书签管理器

团队共享的书签/资源导航页，部署在 GitHub Pages：https://grace-hub-lab.github.io/my-bookmarks/

- `data.json` 是**加密存储**的，输入团队密码后才能查看
- 管理员用 GitHub Token 登录后，增删改会**加密后直接提交到仓库**，其他人约 1 分钟内刷新可见
- 纯静态页面（`index.html` + `data.json`），没有后端、没有依赖

## 文件

| 文件 | 说明 |
|---|---|
| `index.html` | 页面和全部逻辑 |
| `data.json` | 加密后的书签数据（网页保存时自动更新，**不要手动改**） |

## 日常使用

### 浏览（所有人）

- 第一次打开需要输入**团队密码**（向管理员获取），勾选「记住」后本浏览器不用再输
- 顶栏「🔒 锁定」可以清除本浏览器保存的密码
- 左侧栏按分类筛选，顶部搜索框可搜标题、描述、分类、URL
- 点击表头「标题」「分类」排序
- 点每行前面的 ☆ 收藏，收藏的资源**置顶显示**，也可以在「⭐ 我的收藏」里单独查看
  - 收藏只保存在自己的浏览器里，不影响别人
- 标题旁显示「最后更新」时间和最近一次修改内容，点击可查看完整修改历史
- 页面每分钟自动拉取最新数据，也可以点左侧「🔄 刷新数据」

### 管理（需要 GitHub Token）

1. 点右上角「🔑 管理员登录」，粘贴 Token（获取方法见下文）
2. 登录后可以：
   - **＋ 添加资源**：分类可选已有的，也可以直接输入新名字（如 `Jira`），会自动新建分类
   - **编辑 / 删除**：在表格最右侧「操作」列
   - **📥 批量导入**：见下文
3. 保存后立即提交到 GitHub，无需任何手动上传

添加时如果 URL 已经存在，会提示是哪条重复，确认后才会保存。

### 批量导入

支持两种文件：

- **浏览器书签 HTML**：Chrome / Edge 打开书签管理器 → 右上角 ⋮ → 导出书签
- **本站导出的 `data.json`**：用于从备份恢复

导入前会显示预览：

- 分类方式可选「按书签文件夹名作为分类」或「全部归入同一个分类」
- 已存在的链接会标记出来，默认不导入
- 可以逐条勾选要导入的内容

### 备份与恢复

- 「💾 导出备份」会把当前全部数据下载为 `bookmarks-backup.json`
  - ⚠️ 备份文件是**明文**，只保存在本地，不要上传到仓库或其他公开位置
- GitHub 也保存了每次修改（加密的），仓库里打开 `data.json` → **History** 可以回到旧版本
  - 回到旧版本后，需要用**当时的**团队密码才能解开
- 误删后恢复：用「📥 批量导入」导入备份文件（ID 会保留，个人收藏不会丢）

## 数据加密

### 原理

- 用团队密码通过 PBKDF2-SHA256（60 万次迭代）派生出 AES-256-GCM 密钥，在浏览器里加密/解密
- `data.json` 里只有密文；没有密码，即使下载了文件也看不到内容
- 浏览器里保存的是派生出的密钥，不是明文密码
- 提交记录是公开的，所以提交信息只写 `Add bookmark` / `Update bookmark` 这类通用描述，不包含标题

### 设置 / 更换团队密码

管理员登录后点左侧「🔐 团队密码」：

1. 点「随机生成」得到一个长密码（推荐），或自己输入至少 12 位
2. 保存后数据会用新密码重新加密
3. 把新密码**私下**发给同事（私聊，不要发在群里或写进任何文档仓库）

其他人下次打开页面会被要求输入新密码。

**什么时候需要换密码**：有人离开团队、怀疑密码泄露、或定期轮换。

### 注意

- 密文是公开的，别人可以离线反复猜密码 → 一定要用**随机长密码**
- **忘记密码 = 数据无法恢复**。管理员请自己保存好密码，并定期「导出备份」到本地
- 加密只保护书签内容。仓库名、页面本身、提交时间仍然是公开的

## GitHub Token

管理员登录用的是 GitHub **Fine-grained personal access token**，它就是写入仓库的钥匙。

### 创建

1. 打开 https://github.com/settings/personal-access-tokens/new
2. **Resource owner** 选 `Grace-hub-lab`
3. **Expiration** 建议选 90 天或自定义一年
4. **Repository access** 选 *Only select repositories* → `my-bookmarks`
5. **Permissions** → Add permissions → **Contents: Read and write**
6. 生成后复制 Token（只显示一次）

### 过期了怎么办

Token 过期或被撤销时，网页会自动退出管理员模式并弹出登录框提示。处理方法：

1. 打开 https://github.com/settings/personal-access-tokens
2. 点开对应 Token → **Regenerate token**
3. 用新 Token 重新登录

### 注意

- Token 只粘贴到网站登录框，**不要发到聊天、邮件或提交到仓库**
- 如果不小心泄露，立刻到上面的页面 Delete 或 Regenerate
- 勾选「在本浏览器记住 Token」后，Token 保存在该浏览器的 localStorage；公用电脑上不要勾选

## 部署

1. 仓库设置为 Public
2. Settings → Pages → Source 选 **Deploy from a branch**，Branch 选 `main` / `(root)`
3. 上传 `index.html` 和 `data.json`

更新页面功能时只需重新上传 `index.html`。**不要用本地的 `data.json` 覆盖线上版本**，否则会丢掉网页上新增的书签，或者把明文传上去。

### 新建仓库时的初始化

新仓库里的 `data.json` 内容先放一个空数组：

```json
[]
```

然后打开网站 → 管理员登录 → 「🔐 设置团队密码」→ 「📥 批量导入」备份文件。这样仓库历史里从头到尾都不会出现明文书签。

如果仓库名或账号变了，修改 `index.html` 顶部的配置：

```javascript
const GH_OWNER = 'Grace-hub-lab';
const GH_REPO = 'my-bookmarks';
const GH_BRANCH = 'main';
```

## data.json 格式

仓库里存的是加密格式：

```json
{
  "encrypted": true,
  "version": 1,
  "kdf": "PBKDF2-SHA256",
  "iterations": 600000,
  "salt": "...",
  "iv": "...",
  "data": "...密文..."
}
```

解密后（以及「导出备份」得到的文件）是下面的书签数组：

```json
[
  {
    "id": 1776070940904,
    "title": "资源标题",
    "url": "https://example.com",
    "category": "wiki",
    "description": "资源描述"
  }
]
```

| 字段 | 说明 |
|---|---|
| `id` | 唯一数字 ID（添加时自动生成） |
| `title` | 标题，必填 |
| `url` | 链接，必填，需以 `http://` 或 `https://` 开头 |
| `category` | 分类。内置 `tool` / `wiki` / `quip`（显示为 工具 / Wiki / Quip），其他值直接作为分类名显示 |
| `description` | 描述，可选 |

## 常见问题

**别人看不到我刚加的书签？**
GitHub Pages 重新发布需要约 1 分钟，让对方稍后刷新即可。可以在页面上的「最后更新」确认提交是否成功。

**保存时提示「没有仓库写权限」？**
Token 缺少 Contents: Read and write 权限，到 GitHub 上编辑该 Token 补上权限。

**同事说密码不对？**
可能是密码刚被更换过，把最新的团队密码再发给他。

**页面提示「数据未加密」，不能编辑？**
这是保护措施：数据加密前禁止保存，防止明文被提交。管理员点「🔐 设置团队密码」即可。

**两个人同时编辑会冲突吗？**
不会。每次保存都基于仓库里的最新数据修改，遇到冲突自动重试。
